# Artifact Generation Workflow v1.0

## Purpose
This workflow governs creation, testing, and repository tracking for diegetic artifact assets used in The Hollow Spire.

## Required Order
1. Identify the page and narrative purpose.
2. Complete Phase 0 Canon Review.
3. Update the Artifact Library Registry before generation.
4. Decide whether heraldry is justified.
5. Generate one asset at a time.
6. Test the asset in Homebrewery at intended placement.
7. Update the registry after placement.
8. Include the final asset, updated registry, updated source snapshot, and changelog in the next push package.

## One-Asset Rule
Generate only one production artifact at a time until its visual style, readability, and placement are approved.

Asset overview sheets are allowed only for concept exploration. They are not production assets.

## Production Asset Requirements
Each production asset must have:
- Unique filename
- Version number
- Intended page
- Intended dimensions or placement area
- Source/owner/faction decision
- Crest/seal decision
- Registry entry
- Homebrewery source reference

## Naming Pattern
Use this pattern:

`Chapter00_Artifact_###_<ShortName>_vX.X.png`

Examples:
- `Chapter00_Artifact_001_Explorer_Field_Note_v1.0.png`
- `Chapter00_Artifact_002_Guild_Training_Excerpt_v1.0.png`

## Registry Update Rule
The Artifact Library Registry must be updated:
- before generating a new asset,
- after selecting an approved version,
- after placing the asset in Homebrewery,
- whenever an asset is renamed, replaced, retired, or moved.

No artifact asset should be considered locked unless the registry reflects the current asset status.

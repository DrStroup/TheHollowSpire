# Explorer's Codex and Hunts — one system

Status: Accepted system relationship; detailed mechanics incomplete.
Audience: GM / designer.
Decision: CAN-002 in [DECISIONS.md](../../00_Project_Status/DECISIONS.md).

The Explorer's Codex and Hunts are one integrated system. “Hunt” remains a term for a type of investigation or activity within that system, not an independent progression system to build alongside it.

The user's prior correction established the merger. It did not supply a complete integration specification. Preserve existing observations, samples, chips, and discovery records; do not invent ranks, currencies, rewards, or automatic unlock mechanics.

## Existing supported behavior

The Codex is an ancient containment-record device covering fauna, flora, anomalies, phenomena, and lost expeditions. Exploration can reveal entries, evidence, samples, chips, and archive records.

Hunt activities are discovered through exploration and evidence. Existing types are Observation, Harvest, Containment, and Extermination. Record their evidence and stage alongside the related Codex entry.

An ordinary contract to hunt a creature is not automatically a formal Codex Hunt. Do not force the formal Hunt system onto every hunting request.

## One record, several views

A finding can appear in a floor checklist, encounter checklist, and Codex/Hunt record, but counts once toward Discovery. The same occurrence must use the same award key. “Hunt” may remain an activity tag; it does not imply a second independent point award or progression total.

## Still open

- Exact entry/stage schema and completion requirements.
- How chips, samples, and Hunt completion interact.
- Timing of damaged device acquisition versus activation.
- Reward tuning and any migrated legacy records.

These are open implementation questions, not permission to restore separate Hunt and Codex systems.

# Publication Audit Rules v1.1

## Status

Current audit standard for Book 01 publication development.

This file supersedes Publication_Audit_Rules_v1.0.

## Mandatory Audit Order

Before creating new manuscript content:

1. Audit existing manuscripts.
2. Audit existing Homebrewery content.
3. Audit existing canon files.
4. Identify overlaps, contradictions, duplicates, and missing sections.
5. Produce or update the audit report.
6. Only then proceed with new writing.

Do not rewrite existing manuscript content until the relevant audit section is complete.

## System-Neutral Publication Checks

Flag publication-facing text that directly names or depends on proprietary fantasy roleplaying brands, product lines, settings, monsters, or protected terminology.

Publication-facing text should prefer generic language such as:

- fantasy roleplaying game
- adventuring party
- explorer
- game master
- character level
- core rules
- bestiary
- expedition
- encounter
- training
- special ability

Internal notes may retain rules-reference assumptions when required for balancing, but those references should not appear in final manuscript text unless explicitly isolated as internal development material.

## Deprecated Terminology Checks

Flag and correct the following when found in publication-facing or current canon files:

- Guild Marks
- Pathfinder-specific terminology
- D&D-specific terminology
- Direct references to proprietary rulebooks or product names
- Older Book 01 ranges that stop at Floor 10 instead of Floor 12
- Older Chapter 0 title references such as Running the Spire when the current publication title is The Explorer Guild Primer

## Reward Audit Standard

Rewards should follow the Meaningful Reward Philosophy.

The audit should not require every reward to be discovery-based. Instead, each reward should be evaluated for whether it creates meaningful advancement without relying primarily on currency.

Supported reward categories include:

- Discovery rewards
- Material rewards
- Monster-part rewards
- Training rewards
- Access rewards
- Route and travel rewards
- Settlement and service rewards
- Equipment and tool rewards
- Reputation and relationship rewards
- Narrative progression rewards

## Reward Red Flags

Flag any reward that:

- Uses Guild Marks.
- Offers only coin or generic payment.
- Treats wealth as the primary reason to explore.
- Ignores obvious monster-part or environmental material opportunities.
- Misses a chance for training, mentorship, access, or route improvement.
- Uses proprietary mechanical language in publication-facing text.

## Reward Opportunity Checks

For every encounter, contract, location, and floor milestone, ask whether it could support one or more of the following:

- Monster drops such as Iron Rat Whiskers.
- Crafting or repair materials.
- Training from a local expert, survivor, guild member, or settlement leader.
- A new special ability or expedition technique.
- Access to a new quest giver.
- Access to a locked service, archive, outpost, or settlement function.
- Faster travel, safer backtracking, or a new route.
- Settlement improvement that makes the world better.
- A clue, map, record, witness, or revelation.

## Canon Consistency Checks

Current Book 01 canon includes:

- Explorer Guild
- Seven Seals
- Moon Lantern progression
- Cycle of Recurrence
- Warden Ledger
- Truth as the First Seal
- Emberlight Village
- Blackwater Run
- Lantern Village
- Book 01 covering Floors 1-12
- Region 001 canon as authoritative unless a newer audit explicitly supersedes it

Flag documents that contradict these points.

## Audit Classification Labels

Use the following labels consistently:

- Complete
- Partial
- Outdated
- Contradicted by newer canon
- Needs rewrite
- Publication Ready
- Locked

## Required Audit Table Format

Use this structure when auditing sections or files:

| Section or File | Status | Action |
|---|---:|---|
| Example | Partial | Expand |
| Example | Complete | Lock |
| Example | Outdated | Rewrite |

## Priority Rule

If a framework conflict exists, resolve the framework before drafting new prose.

If a canon conflict exists, resolve canon before layout.

If a Homebrewery conflict exists, resolve source before PDF export.

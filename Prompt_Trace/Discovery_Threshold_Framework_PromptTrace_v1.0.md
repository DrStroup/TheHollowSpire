# Discovery Threshold Framework v1.0 — Prompt Trace

## Origin

The framework emerged while building the Floor 001 registries.

The user proposed gating certain quests behind hidden Discovery thresholds.

Example:
- Floor 1 / Region 001 contains many possible Discovery points.
- The party reaches Emberlight with 49 Discovery.
- The Guild attendant has no task yet.
- The party explores more and reaches 51 Discovery.
- A hidden 50 Discovery threshold is crossed.
- The Guild attendant now offers a new task or information.

## Key Decision

Discovery is a semi-hidden DM-facing mechanic.

Players do not see Discovery numbers.

The system is expressed in-world through:

- Lantern brightness.
- NPC recognition.
- Guild confidence.
- Contract availability.
- Rumors.
- Trust.
- Access.

## Important User Lock

Discovery should be expressed to players through cues like:

"Wow, your lantern sure glows bright."

This preserves immersion and prevents players from treating Discovery as a visible optimization score.

## Design Purpose

The system rewards exploration without forcing it.

It makes curiosity valuable.

It aligns the campaign's mechanical progression with its core theme:

Exploration matters.
